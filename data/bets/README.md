# 買い目ファイルの形式

朝の予想タスクがここへ `YYYY-MM-DD.json` を1つコミットする。
**このファイルが予想する側と検算する側の唯一の接点**であり、
検算側（`check.py`）はこの JSON しか見ない。

将来 Claude API が印を打つようになっても、同じ形を吐きさえすれば
検算側は一切変更しなくてよい（`source` にどこが作ったかを記録する）。

**2026-08-14〜、印と買い目の確定タイミングを分離した。** 朝タスクが書くのは
`marks`・`partners`・`subjective_hit_rate` まで。`bets`（買い目）と
`confidence`（勝負度）は書かない（書いても直前検算が実オッズで上書きする）。
理由は予想メソッド 第13章「印と買い目組み立ての分離」を参照。実際に発注可能な
最終形は、直前検算（`check.py`→`bet_builder.py`）が実オッズで組み立てて
このファイルへ書き戻したあとの状態である。

## 例（朝タスクの出力）

`bets`・`confidence` はまだ書かない。直前検算が実オッズで確定する。

```json
{
  "date": "2026-08-02",
  "generated_at": "2026-08-02T07:31:00+09:00",
  "source": "cowork",
  "races": [
    {
      "race_id": "202601020811",
      "name": "クイーンステークス",
      "venue": "札幌",
      "race_no": 11,
      "start_time": "15:25",
      "subjective_hit_rate": 0.16,
      "marks": [
        {"mark": "◎", "umaban": 7, "steps": [1, 3, 5]},
        {"mark": "○", "umaban": 11, "steps": [3]},
        {"mark": "▲", "umaban": 2, "steps": [4]},
        {"mark": "△", "umaban": 3},
        {"mark": "△", "umaban": 14}
      ],
      "partners": [
        {"umaban": 9, "reason": "前走出遅れで着順以上に上がりが速い"}
      ],
      "bets": [],
      "note": "危険な人気馬: 9エリカエクスプレス（洋芝初・休み明け・前走逃げて好走）"
    }
  ]
}
```

## 例（直前検算後の最終形）

`check.py`→`bet_builder.py` が実オッズから `bets`・`confidence` を埋めて
このファイルへ書き戻す。相手プールは○→▲→△→中穴候補の優先順で並ぶため、
印の上位馬（◎○）が相手から外れ下位の印だけが残る、という矛盾は構造的に
起きない（2026-08-02クイーンSの事故の再発防止。予想メソッド第13章F案）。

```json
{
  "race_id": "202601020811",
  "confidence": "B",
  "bets": [
    {"type": "馬連", "horses": [7, 11], "stake": 100},
    {"type": "馬連", "horses": [7, 2],  "stake": 100},
    {"type": "馬連", "horses": [7, 3],  "stake": 100},
    {"type": "馬連", "horses": [7, 14], "stake": 100}
  ]
}
```

## 項目

| 項目 | 必須 | 内容 |
|---|---|---|
| `date` | ✅ | 開催日 `YYYY-MM-DD` |
| `generated_at` | | 朝タスクの完了時刻（外部確認済みJST） |
| `source` | | `cowork` / 将来は `claude-api` など |
| `org` | | `jra`（既定）/ `nar`。**オッズと結果の取得先がこれで決まる** |
| `race_id` | ✅ | 12桁。中央は `年(4)+場コード(2)+回(2)+日(2)+R(2)`、地方は `YYYYMMDD+場コード(2)+R(2)` |
| `start_time` | ✅ | `HH:MM`。**発走済みガードに使うので必ず入れる** |
| `confidence` | | 勝負度 `A`/`B`/`C`。**朝タスクは書かない。直前検算が実オッズで確定する** |
| `subjective_hit_rate` | ✅ | 主観的中率 0.0〜1.0。**期待値1.2の判定に使う。朝タスクが書く** |
| `marks` | ✅ | `◎○▲△`。△は複数可。`steps` は任意（下記） |
| `partners` | | 中穴候補。`[{"umaban": 9, "reason": "..."}]`。朝タスクが書く（下記） |
| `bets` | | 券種は `単勝` `複勝` `馬連` `ワイド` `馬単` `3連複`。**朝タスクは書かない** |
| `venue` `race_no` `note` | | 表示用 |

中央の場コード: 札幌`01` 函館`02` 福島`03` 新潟`04` 東京`05` 中山`06` 中京`07` 京都`08` 阪神`09` 小倉`10`

地方の場コード: 門別`30` 盛岡`35` 水沢`36` 浦和`42` 船橋`43` 大井`44` 川崎`45`
金沢`46` 笠松`47` 名古屋`48` 園田`50` 姫路`51` 高知`54` 佐賀`55`
（`nar.VENUE_CODES` が正本。一度決めたら変えない — 過去の買い目の race_id が引けなくなる）

## 中央と地方を1つのファイルに混ぜてよい

土曜に中央の重賞と地方の重賞が両方ある日は、同じ `YYYY-MM-DD.json` の
`races` に並べる。レースごとに `org` を持つので取得先はレース単位で決まる。

**`race_id` は中央も地方も12桁の数字で、数字だけでは見分けが付かない。**
判別は `org` だけで行い、race_id の中身から推測しないこと。
`org` の無い過去のファイルはすべて中央として読む（このリポジトリが
先に中央だけで動いていたため）。

```json
{
  "race_id": "202608124711",
  "org": "nar",
  "name": "くろゆり賞",
  "venue": "笠松",
  "race_no": 11,
  "start_time": "16:35"
}
```

地方はナイターがあり、発走は **16:30〜21:00 台**に散らばる。
`start_time` を省くと発走済みガードが効かない。

## 手順タグ（`marks[].steps`、2026-08-12 追加・後ろ向き研究のための仕込み）

各印に、根拠になった予想メソッド第1章「予想の手順（7ステップ）」の番号を
**任意で**付けられる。複数の手順が根拠なら配列で並べる。

```
1 トラックバイアスの設定    5 危険な人気馬の割り出し
2 厩舎コメントの確認        6 印をつける
3 出走馬の絞り込み          7 競馬新聞の印との照合
4 展開予想
```

厳密な統計評価をするにはまだサンプルが足りないが、`note` の自由記述だけでは
「どの手順が効いていないか」を後から集計できない。番号なら書く側の負担も
軽く、半年〜1年分たまれば「手順3の判定が外れた回数」のような分析ができる。
過去分（`steps` の無い買い目）は遡って埋められないので、ここから先の分だけが
対象になる。1〜7以外の番号は `check.py` の読み込み時にはじかれる。

## 中穴候補（`partners`、2026-08-14 追加）

印を打たなかったが、7ステップの分析シート上でプラス材料があった馬。
第13章「相手の広げ方」が指示する候補プールで、直前検算の買い目組み立てが
`marks`（○▲△の優先順）に続けてこの順で使う。

```json
"partners": [
  {"umaban": 9, "reason": "前走出遅れで着順以上に上がりが速い"},
  {"umaban": 5, "reason": "距離短縮でプラス材料"}
]
```

`reason` は省略できるが、後から「なぜこの馬を相手候補にしたか」を
振り返れるよう、短くても書くこと。

## 注意

- **`subjective_hit_rate` を省くと期待値を検算できない。** 第13章の基準の半分が
  効かなくなるので必ず入れること。
- **`bets`・`confidence` は朝タスクが書かない。** 書いても直前検算が実オッズで
  上書きする（毎回の検算で最新のオッズを使って組み直す。結果はロックしない）。
- 勝負度Cのレースに `bets` を入れると発注が止まる（第13章「Cは購入しない」）。
- 形式違反はすべて `check.py` が起動時にはじき、理由を出す。
