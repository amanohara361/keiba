# 昼の見直し手順（土日 12:17 JST）

朝の印は、前夜〜未明のカードに入っている馬場状態を前提に打っている。
昼までに馬場が回復・悪化したり、当日の下級条件で強い偏りが出たりすると、
その前提で上げ下げした馬の評価がずれる。**実測した馬場とバイアスが朝の前提と
食い違ったレースだけ**、印と主観勝率を直す手番を1つ置く。

きっかけ：2026-09-27、朝は中山を全レース「重」前提で印を打ったが、昼には
「稍重」に回復していた。スプリンターズSの◎15は重実績を理由に勝率を
市場の1.5倍へ上げていたが、それを直す手段が無かった。経緯は `docs/決定ログ.md`。

## 1日の流れ

| 時刻 (JST) | 何が | 何をする |
|---|---|---|
| 07:00 | 朝の予想（Routine） | 印・partners・win_probabilities を push |
| 11:37 | `bias.yml`（Actions・定時） | 午前の確定レースから馬場とバイアスを測り `data/bias/YYYY-MM-DD.txt` へ |
| **12:17** | **昼の見直し（Routine・本手順）** | 食い違ったレースだけ印と勝率を直して push |
| 13:07 / 14:07 | 直前検算（`check.yml`） | 実オッズで買い目を組む。見直し後の印を使う |

`bias.yml` の定時実行は最大85分遅れるので、見直しのセッションは測定が古ければ
`workflow_dispatch` で起こし直す（手動起動は遅れない）。

## 直してよい条件（トリガー）

メソッド第4章は「直前に直感で買い目を変えるのが最も危険」と言っている。
だから**直す条件を先に決めておき、それ以外では触らない。**

| | 条件 | 判定に使うもの |
|---|---|---|
| T1 馬場の変化 | 朝の前提と、同じ場・同じ馬場種別（芝／ダ）で最後に確定したレースの馬場状態が**1段階以上**違う（良・稍重・重・不良） | 朝＝カードの `conditions.going`、昼＝`data/bias/` の表の「状態」列 |
| T2 強いバイアス | その場・馬場種別の判定に **★** が出ていて、測れたレースが**4鞍以上** | `data/bias/` の「→ 判定」 |
| T3 朝noteの馬場分岐 | 朝の note に「稍重以上に悪化した場合は…」のような**条件つきの分岐**が書いてあり、その条件が昼の時点で成り立っている | 朝＝note の分岐の文言、昼＝`data/bias/` の同じ場・馬場種別の最新の状態、または当日の馬場発表・天候（スポーツナビの結果ページ、WebSearch のスニペット）。取れた根拠は revisions の reason に書く |

- **T3 の趣旨**：朝のうちに「こうなったらこう直す」と決めてあった分岐を実行するだけで、昼に新しい判断を足さない。
  朝 note に分岐が書いてあるのに、昼に誰も点検しなかったのが 2026-10-04 の京都大賞典・大原S・藤森S
  （雨で稍重に悪化、分岐は未発動のまま。`検証ノート.md` 2026-10-05）。T1 は `data/bias/` の測定（11:37）が
  拾った馬場しか見ないので、測定後に雨で悪化した場合を拾えない。T3 はそこを補う。
- T3 は分岐の通りに直す。分岐に無い馬を動かさない。朝 note に分岐が無いレースでは T3 は発動しない
  （分岐の書き漏れは朝タスク側の問題。ここで補わない）。
- どれにも当たらないレースは**ファイルに触らない**（報告に「据え置き」と書くだけ）。
- 「蓄積不足のため1.00を仮基準」と出ているダートの判定は、第11章の注意どおり割り引く。
  T2 は芝のみで使い、ダートは T1 だけで判断する（蓄積が100鞍を超えたら見直す）。
- 当日の横比較（CLAUDE.md「バイアス判定は必ず同日横比較まで行う」）を守る。
  1鞍の印象で動かさない。

## 直してよい範囲

- **発走45分前を過ぎたレースは触らない**（push→直前検算の反映に時間が要る）。
- **1レースにつき1回まで。**昼に何度も書き換えない。
- 動かしてよいのは、**朝の note で馬場・展開を理由に上げ下げした部分**だけ。
  例：「重2-0-0-0で市場の1.5倍へ」→ 稍重なら市場寄りに戻す。
- 新しく印を付けてよい馬は、朝の `partners` か note で個別に吟味済みの馬に限る。
  朝に見ていない馬を昼に拾わない（直感の混入を防ぐ）。
- `win_probabilities` の規則は朝と同じ（`docs/朝タスク手順.md`）。
  合計1.0未満、市場から動かすなら根拠を note に書く。
- 判断は朝と同じく Opus を high で使う（CLAUDE.md。印付けは根幹）。

## 記録の仕方

直したレースには、`revisions` に1件追加する（形式は `data/bets/README.md`）。
**書き換える前の印と勝率を必ず残す。**朝の印と見直し後の印のどちらが当たったかを
後から比べないと、この手番が役に立っているのか分からないため。

```json
"revisions": [{
  "at": "2026-09-27T12:40:00+09:00",
  "trigger": "T1 馬場の変化（芝 重→稍重）",
  "reason": "◎15は重実績で市場0.114→0.17に上げていた。稍重なので0.14に戻す。印は据え置き",
  "marks_before": [{"mark": "◎", "umaban": 15, "steps": [1, 3, 4, 6]}],
  "win_probabilities_before": {"15": 0.17, "8": 0.06, "9": 0.14}
}]
```

`note` の末尾にも「【昼の見直し】…」と1行足す（メールで読む人向け）。

## 自動起動プロンプト

Routine 名：`競馬 昼の見直し（土日 12:17 JST）`
cron：`17 3 * * 6,0`（UTC。土日 03:17 UTC ＝ 12:17 JST）

```text
土日の昼の見直しタスク。自動起動なので人は見ていない。判断は自分で完結させること。

0. リポジトリを用意する（朝の予想と同じ）。CLAUDE.md が読めなければ
   mcp__Claude_Code_Remote__add_repo を owner: "amanohara361", repo: "keiba",
   access: "push" で呼び、clone して register_repo_root で登録し、cd する。
   リポジトリ名を推測して他を clone しない。

1. CLAUDE.md / docs/昼の見直し手順.md / docs/朝タスク手順.md を読む。
   手順の正本は docs/昼の見直し手順.md。
2. 現在時刻を確定する（CLAUDE.md「現在時刻の確定」）。
3. git pull origin main。data/bets/YYYY-MM-DD.json が無ければ何もせず終わる。
4. data/bias/YYYY-MM-DD.txt の「測定時刻」が60分以上前、または無ければ、
   actions_run_trigger で workflow: bias.yml, ref: main, inputs.date: YYYYMMDD
   を起こし、完了を待って git pull する。actions_run_trigger がこのセッションで
   使えない場合も含め、新しい測定が取れなければ「バイアス未取得のため据え置き」
   と報告して終わる（推測で直さない。このセッションからは netkeiba に到達
   できないので、jra_bias.py live を自分で回そうとしない）。
5. 発走まで45分以上あるレースだけを対象に、docs/昼の見直し手順.md のトリガー
   （T1 馬場の変化／T2 強いバイアス／T3 朝noteの馬場分岐）を判定する。
   T3 は朝の note に「悪化した場合は…」の分岐が書いてあるレースを洗い出し、
   最新の馬場状態（data/bias、取れなければ馬場発表・天候の検索）と突き合わせる。当たらないレースは触らない。
6. 当たったレースだけ、Agent（model: opus）に朝の note・カード・
   data/bias の該当部分を渡し、「直してよい範囲」の中で印と
   win_probabilities を見直させる。revisions に書き換え前の値を残し、
   note に【昼の見直し】を1行足す。
7. python make_bets.py --show が終了コード0であることを確認する。
8. 直したレースがあれば git add data/bets/ && git commit && git push origin main。
   PR は作らない。check.yml は push で自動起動するので手動起動しない。
   .py にバグを見つけたら直 push せず、別ブランチで PR を作る（朝と同じ）。

最後に、見直したレース（トリガー・何をどう直したか）と、据え置いたレースを
3〜5行で報告する。直したレースがあればプッシュ通知を送る。
```
