# 地方の見直し手順（毎日 18:20 JST・対象がある日だけ）

地方のナイター重賞（発走 16:30〜21:00 台）は、朝の予想のあとに**同じ日の前半のレースが走る**。
その前半から測ったバイアスで、朝の印の前提が崩れたレースだけ、印と主観勝率を直す手番を1つ置く。
中央の `docs/昼の見直し手順.md` の地方版。**共通の考え方・直してよい範囲・記録の仕方（`revisions`）は
向こうが正本**で、ここには違うところだけを書く。

きっかけ：2026-10-20、鎌倉記念の外れ分析で地方の当日バイアスが取れていないと分かった
（`docs/決定ログ.md` 2026-10-20）。週次レビューの「当日の地方バイアス」表は**後から全日分を測った値**で、
発走前に使える値ではない。**予想に使えるのは、その時点で保存した `data/bias/nar/` の測定だけ**。

---

## 1日の流れ

| 時刻 (JST) | 何が | 何をする |
|---|---|---|
| 08:00 | 地方の予想（Routine） | 印・partners・win_probabilities を push |
| 18:07 | `nar_bias.yml`（Actions・定時） | その時点の確定レースから測り `data/bias/nar/YYYY-MM-DD.txt` へ |
| **18:20** | **地方の見直し（Routine・本手順）** | 食い違ったレースだけ印と勝率を直して push |
| 18:37 | 直前検算（`nar_check.yml`） | 実オッズで買い目を組む。見直し後の印を使う |
| 19:07 | `nar_bias.yml`（2回目） | 19:37 の検算以降のための測り直し（見直しの2回目は置かない） |

定時実行は遅れるのが普通。見直しのセッションは測定が古ければ `workflow_dispatch` で `nar_bias.yml` を起こし直す。

---

## 直してよい条件

中央の T2・T3 だけを使う。**T1（馬場の変化）は使わない**：地方のカードに朝の馬場状態が入っていないことが多い
（検算に「馬場状態がまだ発表されていません」と出る）ので、比べる朝の前提が無い。

| | 条件 | 判定に使うもの |
|---|---|---|
| T2 強いバイアス | その場の判定に **★** が出ていて、測れたレースが**4鞍以上** | `data/bias/nar/` の「→ 判定」 |
| T3 朝noteの馬場分岐 | 朝の note に「不良になれば…」のような条件つきの分岐があり、その条件が成り立っている | 朝＝note、夕＝`data/bias/nar/` の馬場の列 |

- **地方ダートの平常値は実データ（200R前後）から出している**ので、中央ダートと違い T2 を使ってよい。
  ただし1場3鞍未満は判断保留、4鞍未満は触らない。
- 同じ場の**別の日の傾向を持ち込まない**。測れたその日の横比較だけを根拠にする。
- どれにも当たらないレースは**ファイルに触らない**。

## 直してよい範囲・記録

中央と同じ（`docs/昼の見直し手順.md`「直してよい範囲」「記録の仕方」）。要点：
- 発走45分前を過ぎたレースは触らない。1レースにつき1回まで。
- 動かすのは、朝の note で馬場・展開を理由に上げ下げした部分だけ。朝に見ていない馬を拾わない。
- `revisions` に書き換え前の印と勝率を残し、`note` の末尾に「【地方の見直し】…」を1行足す。
- 判断は Opus を high で使う。

## 自動起動プロンプト（未作成。Routine は画面から作る）

Routine 名：`競馬 地方の見直し（毎日 18:20 JST）`
cron：`20 9 * * *`（UTC。毎日 09:20 UTC ＝ 18:20 JST）

```text
地方の見直しタスク。自動起動なので人は見ていない。判断は自分で完結させること。

0. リポジトリを用意する（地方の予想と同じ）。CLAUDE.md が読めなければ
   mcp__Claude_Code_Remote__add_repo を owner: "amanohara361", repo: "keiba",
   access: "push" で呼び、clone して register_repo_root で登録し、cd する。
   リポジトリ名を推測して他を clone しない。

1. CLAUDE.md / docs/地方の見直し手順.md / docs/昼の見直し手順.md を読む。
   手順の正本は docs/地方の見直し手順.md（共通部分は昼の見直し手順）。
2. 現在時刻を確定する（CLAUDE.md「現在時刻の確定」）。
3. git pull origin main。data/bets/YYYY-MM-DD.json に地方（org: nar）のレースが無ければ
   「対象なし」と報告して終わる。
4. data/bias/nar/YYYY-MM-DD.txt の「測定時刻」が60分以上前、または無ければ、
   actions_run_trigger で workflow: nar_bias.yml, ref: main, inputs.date: YYYYMMDD
   を起こし、完了を待って git pull する。起こせない／新しい測定が取れなければ
   「バイアス未取得のため据え置き」と報告して終わる（推測で直さない）。
5. 発走まで45分以上ある地方のレースだけを対象に、T2・T3 を判定する。当たらないレースは触らない。
6. 当たったレースだけ、Agent（model: opus）に朝の note・カード・data/bias/nar の
   該当部分を渡し、「直してよい範囲」の中で印と win_probabilities を見直させる。
   revisions に書き換え前の値を残し、note に【地方の見直し】を1行足す。
7. python make_bets.py --show が終了コード0であることを確認する。
8. 直したレースがあれば git add data/bets/ && git commit && git push origin main。
   PR は作らない。.py にバグを見つけたら直 push せず、別ブランチで PR を作る。

最後に、見直したレース（トリガー・何をどう直したか）と、据え置いたレースを
3〜5行で報告する。直したレースがあればプッシュ通知を送る。
```
