# 地方競馬（NAR）の予想手順

**毎日**の朝、クラウドのセッションがこの手順で地方の重賞・準重賞の買い目を作る。
`docs/朝タスク手順.md`（中央・土日）の地方版で、**違うところだけ**をここに書く。
共通のこと（現在時刻の確定、第13章の規律、買い目JSONの書き方、
メソッド系ファイルを編集しないこと）は向こうの手順書が正本。

---

## なぜ別の仕組みが要るのか

中央は土日にしか開催しない。地方は**毎日どこかでやっていて、重賞も平日に組まれる**。

2026年8月の12日間（8/1〜8/12）で重賞・準重賞は16鞍あり、その大半が平日だった。
土日固定の仕組みは、この16鞍を1つも拾えない。

取得の制約も逆を向いている。

| | 中央 | 地方 |
|---|---|---|
| 一次情報 | netkeiba の HTML | keiba.go.jp の公式CSV（ZIP） |
| Claude のセッションから | **到達できない**（403） | **到達できる**（実測 200 / application/zip） |
| クラス | アイコン番号から推測 | `競走種類名称` に 重賞／準重賞 と書いてある |
| 1頭あたりの取得 | 3ページ × 1.5秒 | 0回（出馬表CSVに全部入っている） |
| 開催 | 土日 | 毎日 |
| 発走 | 昼〜夕方 | **16:30〜21:00 台（ナイター）** |

クラスが条文で書かれているので、中央で起きた「浜名湖特別（2勝クラス）が
G2に化けて1次スクリーニングを素通りした」事故は、地方では構造的に起きない。

## 自動起動（Routine）

| 項目 | 値 |
|---|---|
| 名前 | `競馬 地方の予想（毎日 08:00 JST）` |
| cron | `0 23 * * *`（UTC。毎日 23:00 UTC ＝ 翌 08:00 JST） |
| 起動の仕方 | 毎回**新しいセッション**を立てる |
| 通知 | 完了時にプッシュ通知 |

中央の Routine（土日 07:00 JST）とは**1時間ずらしてある**。土日は両方が動くので、
同じ `data/bets/YYYY-MM-DD.json` を同時に書きにいかないようにするため。
地方側は**追記する**（中央の races を消さない）。

**プロンプトの先頭にリポジトリを明示するステップ0が要る。** 2026-08-12、これが
無かったため初回が自動発火・手動発火とも空振りした。真っさらなセッションは
「CLAUDE.md を読む」と言われても、どのリポジトリの CLAUDE.md かを知らない。
詳しくは `docs/決定ログ.md`。

**重賞が無い日のほうが多い。** 何も無ければ数十秒で終わる。
それが正常で、報告も「今日は該当なし」の1行でよい。

### 自動起動プロンプト

```text
地方競馬の予想タスク。自動起動なので人は見ていない。判断は自分で完結させること。

0. **まずリポジトリを用意する。** 新しいセッションには何もクローンされていない。
   ホームディレクトリに CLAUDE.md が読めなければ、まだアタッチされていない証拠。
   `mcp__Claude_Code_Remote__add_repo` を owner: "amanohara361", repo: "keiba",
   access: "push" で呼び、返ってきた clone コマンドを実行し、
   `mcp__Claude_Code_Remote__register_repo_root` で登録してから、
   そのディレクトリに cd してから先へ進む。
   add_repo が使えない場合のみ `git clone https://github.com/amanohara361/keiba.git`
   で読み取りだけ確保し、push できないことを最後の報告に明記する。
   **リポジトリ名を推測して他を clone しない。** 分からなければ「リポジトリを
   特定できない」とだけ報告して終わる。

1. CLAUDE.md / docs/決定ログ.md / docs/地方競馬手順.md を読む。
   **手順の正本は docs/地方競馬手順.md**。以下と食い違ったらそちらに従う。
   共通の作法は docs/朝タスク手順.md にある。
2. git pull origin main
3. 現在時刻を確定する（CLAUDE.md「現在時刻の確定」）。
   確定時刻より後に発走するレースだけを対象にする。
4. python nar_card.py --gate で今日の状態を見る。
   - none    … 今日は重賞・準重賞が無い。**何もせず終わる。**（正常）
   - missing … カードが無い。python nar_card.py を自分で実行して作る
               （公式CSVはこのセッションから取得できる。netkeiba と違う）。
   - run     … data/cards/nar/YYYY-MM-DD.json を読んで先へ進む。
5. カードの races（重賞・準重賞のみ）に予想メソッドの7ステップを適用して印を打つ。
   **jra_horses に馬番が入っているレースは交流重賞**。その馬は
   last_run.note に「中央（JRA）所属」と書いてあり、地方のデータに近走が無い。
   **0走を休み明けと読まないこと。** 近走が要るならカード外で確認し、
   確認できないなら note にそう書く。推測で埋めない。
6. 第13章の規律で買い目を組む。基準を満たせないレースは勝負度Cにして買い目を
   入れない。**数を揃えない。**
7. data/bets/YYYY-MM-DD.json に **org: "nar" を付けて追記**する
   （形式は data/bets/README.md、source は "cloud-nar"）。
   **既にあるファイルの races を消さない。** 土日は中央の買い目が先に入っている。
   start_time・subjective_hit_rate・confidence を必ず入れる。
8. python check.py --no-email で自分の買い目を検算する。BLOCK が出たら組み直すか
   勝負度Cに落とす。オッズは発売前で取れないことが多い（「予想オッズ（発売前）」と
   出る）。それは異常ではないので、合成オッズが出ないことを理由に見送らない。
   14:07 以降の直前検算が実オッズであてる。
9. git add data/bets/ data/cards/ && git commit && git push origin main で
   **main に直接**コミットする。**PR は作らない。**

制約:
- 予想メソッド.md・検証ノート.md・CLAUDE.md は編集しない（承認制）。
- 帯広（ばんえい）は対象外（予想メソッド第14章）。
- パトロールビデオ・厩舎コメントは取れない。取れない情報は無いものとして
  判断し、note に「直前タスクで要確認」と残す。
- 14:07 JST の直前検算より前に push を終える。

最後に、対象レース数・印・買い目・見送った理由を3〜5行で報告する。
今日が「該当なし」なら1行でよい。
```

## 一日の流れ

```
04:07 / 06:07 JST   nar_card.yml    公式CSV → data/cards/nar/YYYY-MM-DD.json
08:00 JST           Routine         印を打つ → data/bets/ に org:"nar" で追記
14:07 / 16:07 /     nar_check.yml   カードを見て、対象がある日だけ検算 → メール
18:37 / 19:37 JST
月 09:17 JST        review.yml      公式CSVの払戻で精算（中央と同じ集計に混ざる）
```

`nar_check.yml` は**対象がある日しか回らない**。地方は毎日開催しているが重賞は
毎日ないので、無条件に回すと「朝の買い目が届いていません」が平日ほぼ毎日鳴り、
2026-08-01 を捕まえるための警報が意味を失う。判定は `nar_card.py --gate`。

| gate | 意味 | 動作 |
|---|---|---|
| `run` | 重賞・準重賞がある | 検算する |
| `none` | 取得できて該当なし | 何もしない（無音。これが正常） |
| `missing` | カードが無い | 取得側が転んでいる → メールで知らせる |

**`none` と `missing` を同じ扱いにしない。** ここを混ぜると、
取得が壊れている日が「今日は無い日」に紛れる。

## カードに入っているもの

`data/cards/nar/YYYY-MM-DD.json`。中央のカードより中身が濃い。
**出馬表CSVだけで第12章の分析シートがほぼ埋まる**（第14章の条文どおり）。

| 項目 | 使う章 |
|---|---|
| `entries[].sire` / `dam` / `broodmare_sire` | 第5章 ダート適性、第12章 |
| `entries[].record_venue` / `record_distance` | 第8章、第9章 条件好転 |
| `entries[].record_dirt_left` / `record_dirt_right` | 第5章（右回り・左回りの巧拙） |
| `entries[].recent_runs`（最大5走。着順・距離・馬場・**通過順**・上がり3F・騎手・馬体重） | 第2章 減点方式、第8章、第11章 |
| `entries[].recent_runs[].style`（逃げ／先行／差し／追い込み） | 第2章「前走逃げて好走」、第5章 |
| `entries[].last_run.distance_change` / `jockey_change` / `days_since` | 第2章 減点方式 |
| `entries[].belongs_jra` | 交流重賞の中央馬。**近走が無いのが正常** |
| `has_furlong_times` | 南関東4場＋園田のみ。第11章の手順1がフル適用できるか |

### 近走はどこから来るか

地方の出馬表CSVには「全成績 9-4-6-15」のような通算成績しか載らない。
だが**月次ファイルの出馬表は確定後に着順・タイム・上がり3F・人気が埋まる**ので、
同じ馬（馬名＋生年月日）を過去の日付から引けば近走が組み上がる。
`nar_card.py` は直近6か月分を落としてこれをやっている。

6か月にしてあるのは、第2章が「6か月以上の休み明け」を減点条件に持つため。
**この範囲に1走も無いこと自体が休み明けの根拠**になる長さが要る。

脚質は、レース一覧CSVの「コーナー通過順」（全馬分が1つの文字列に入る）から
その馬の位置を拾って決めている。区切り文字（`,` `-` `=` 括弧）は
差の大きさを表すだけで、順序の解釈には影響しない。

## 交流重賞では中央馬の近走が欠ける

JpnI/II/III などの交流重賞には中央（JRA）所属馬が出てくる。
**その馬の近走は NAR の公式CSVに1走も無い。** 地方のデータしか入っていないので、
これは欠損ではなく仕様である。

`調教師所属` に `JRA` と書かれているので判別でき、カードでは
`entries[].belongs_jra: true` と `races[].jra_horses: [馬番, ...]` に出る。
`last_run.note` も文言を変えてある。

```
中央馬   … 「中央（JRA）所属。地方のデータに近走は入らない。休み明けではない」
地方馬   … 「直近6か月の地方に出走記録なし（休み明け・移籍初戦・デビュー戦）」
```

**同じ「0走」でも意味が真逆**なので、必ずここを見てから解釈する。
2026-08-11 のクラスターカップJpnIII（盛岡10R）では10頭中4頭が `JRA` だった。

中央馬の近走を埋める経路は、いまのところ無い（netkeiba はこのセッションから
到達できない）。埋まらないまま印を打つなら、その旨を note に残す。

## オッズ

公式のオッズCSV（`type=daily`）は約2分ごとに更新され、全場・全レース・全券種が
1ファイルに入る。だから**レースごとに取り直さない**（`check.py` の `_NarDay` が
1日1回だけ落として配る）。

- 賭式は `単勝 複勝 馬複 ワイド 馬単 ３連複 ３連単` の全角表記。
  第13章で扱う6券種に読み替えている（`馬複`→`馬連`、`３連複`→`3連複`）。
- **発売前は中身が空**（ヘッダだけ）で降ってくる。これを「取得できて0件」と
  扱わないよう、`status` を `yoso`（発売前）にして返す。
- 複勝は下限〜上限の幅を持つが、**下限を返す**。期待値を低く見積もる側に倒して、
  規律の判定が甘くならないようにしてある。

## 確定結果

週次レビュー（月曜）は公式の払戻金CSVと出馬表CSVから精算する。
着順と払戻の形は中央と同じにしてあるので、**集計と分類のコードは分岐しない**。

- **同着はレースにつき複数行**で表される（2026-08 の実データで確認）。
  先頭行だけ見ると片方を落とす。
- 着順が数字でない行（中止・除外・取消）は落とす。0着にしない。
- 検算：払戻金 ÷ 100 が該当組の確定オッズと一致する（CLAUDE.md）。

## まだできないこと

- **特別戦は対象外**。重賞・準重賞だけを拾う。特別まで広げると1日16鞍になり、
  地方向けの1次スクリーニング基準を新設する話になる。重賞が回り始めてから。
- **帯広（ばんえい）は対象外**。距離200mでハロンタイム・上がり3Fが存在せず、
  第11章の実務手順を適用できない（予想メソッド第14章）。
- **交流重賞の中央馬の近走**（上記）。
- **トラックバイアスの実測**。`nar_csv.py` がローカルCSVで判定する仕組みを
  持っているが、`data/cards/nar/` の経路とはまだ繋いでいない。
  第11章の手順は南関東4場＋園田（ハロンタイム収録場）でフル適用できる。
