# wrapup: /clear前の引き継ぎ書き出し

## なぜこのスキルがあるか

このリポジトリの CLAUDE.md には次の方針がある。

> 会話が長くなってきたら、続きの根拠を会話に積まず `docs/決定ログ.md` に書いて
> セッションを切り直す。理由が会話の中にしか無い状態が、いちばん失われやすい。

`/clear` は会話の中身を消す。消える前に「なぜそう判断したか」「何を決めたか」
「まだ終わっていないこと」をファイルに定着させておかないと、次のセッションは
同じ議論をゼロからやり直すか、理由を知らずに前回の決定を元に戻してしまう。
このスキルは、その定着作業を毎回同じ形でやるためのものです。

**会話の全文を保存するスキルではありません。** 全文はClaude Codeのセッション
ログとしてローカルに残る。ここで書くのは、次に読む人（次のセッションの自分）が
議論をやり直さずに続きから動けるだけの「結論と理由」だけ。冗長な要約は
決定ログを読みにくくし、次に使われなくなる。

## 実行手順

1. **この会話を振り返り、3種類の情報を抽出する。**
   - **決定事項**：何かを「こうする」と決めた、または既存のやり方を変えた事実
   - **理由**：なぜそう決めたか（比較した選択肢、反証されたデータ、失敗の経緯など）
   - **未完了タスク**：会話の中で挙がったが、まだ実行・検証していないこと

   雑談や試行錯誤の過程そのものは書かない。決定ログ.md の既存セクションを見ると
   分かるが、「〜を試して失敗した」「〜と分かった」という結論だけが残っており、
   途中のやり取りは残っていない。それに揃える。

2. **決まったことが実質何もない会話なら、書かずに終える。**
   単に質問に答えただけ、調査しただけで何の決定も未完了作業もない場合は
   決定ログに追記する必要はない。その旨をユーザーに伝えて終わる
   （空の見出しだけ追記するのは、ログを読みにくくするので避ける）。

3. **docs/決定ログ.md の末尾に、既存セクションと同じ体裁で追記する。**
   既存ログの見出しは `## 見出し（YYYY-MM-DD）` 形式で、日付は今日の日付
   （システム日時ではなく、確認できる実際の日付）を使う。本文は地の文の
   日本語で、「なぜ」を中心に書く。書式の例：

   ```markdown
   ## <このセッションで決めたことを表す短い見出し>（YYYY-MM-DD）

   <何を決めたか、1〜3文。>

   **理由**：<なぜそう決めたか。比較した選択肢や反証されたデータがあれば書く。>

   **次にやること**：<未完了タスクがあれば列挙。無ければこの行自体を書かない。>
   ```

   複数の議題があった場合は見出しを分けて良い。既存の見出しレベル（`##`）に揃える。

4. **`予想メソッド.md` を含む他のファイルには一切書き込まない。**
   決定ログに書いた内容が予想メソッド本体の変更を必要とする場合でも、
   このスキルの中では編集を行わず、「予想メソッド.md への反映が必要」と
   決定ログか会話内で明記するだけにする。メソッド本体の編集は承認を得て
   別途行うルールがあるため。

5. **書き込み終えたら、追記した見出しをユーザーに短く提示し、
   「/clearしても大丈夫です」という趣旨の一言を伝える。**
   長い説明は不要。何を書いたかが一目で分かれば十分。

## 検証ノート.md との使い分け

`検証ノート.md` は学習ログ（検証・実測の記録）。今回の会話が予想手法の検証結果
（回収率の実測、バイアス判定の検証など）を含む場合は、その部分は決定ログではなく
検証ノート.md に書く方が既存の使い分けに合う。どちらに書くべきか迷う場合は、
「なぜそうするか（設計判断）」→決定ログ、「何を測ってどうだったか（実測結果）」
→検証ノート、という基準で振り分ける。
